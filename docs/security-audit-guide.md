# 🔐 Security Audit — คู่มือการใช้งาน

สกิลตรวจหาช่องโหว่ความปลอดภัยจาก [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) ติดตั้งแบบ global ไว้ที่ `~/.claude/skills/security-audit`

ใช้ตรวจโค้ดได้ทุกแบบ ทั้งเว็บ, API, service, CLI, library และ daemon เน้นอ่านซอร์สโค้ดเป็นหลัก (source-first) และรายงานเฉพาะช่องโหว่ที่ข้ามขอบเขตความปลอดภัยได้จริง พร้อมหลักฐาน วิธีทดสอบที่ปลอดภัย ระดับความสำคัญ และวิธีแก้ที่เล็กที่สุด

---

## 🔀 2 โหมดการทำงาน

| โหมด | เริ่มทำงานเมื่อ | ผลลัพธ์ |
|---|---|---|
| **Guidance** (ค่าเริ่มต้น) | ถามเรื่องความปลอดภัย หรือขอให้ตรวจเฉพาะจุด | ตอบในแชท ไม่สร้างไฟล์ |
| **Full audit** | สั่งตรวจทั้ง codebase, pen test, ตรวจแบบละเอียด หรือขอรายงานเป็นไฟล์ | ทำครบ 6 ขั้นและเขียนรายงานลงโฟลเดอร์ |

ถ้าคำสั่งกำกวม มันจะถามก่อนว่าจะเอาแบบไหน

## 💬 ตัวอย่างคำสั่ง

ไม่มีคำสั่ง `/` ให้พิมพ์ภาษาธรรมดา สกิลจะทำงานเอง

**Guidance (ตรวจเฉพาะจุด)**
- "ระบบล็อกอินนี้มีช่องโหว่ไหม"
- "ตรวจ API endpoint `/api/orders` ว่าคนอื่นดูออเดอร์ของเราได้ไหม"

**Full audit (ตรวจทั้งโปรเจกต์)**
- "security audit this codebase"
- "find security vulnerabilities in ./src"
- "do a security review, output to ~/audits/my-project"

## 🎚️ ระดับความละเอียด (Full audit)

| Profile | ใช้ตอนไหน |
|---|---|
| `quick` | โปรเจกต์เล็ก, ตรวจซ้ำ หรือดูคร่าวๆ รอบแรก |
| `standard` | ค่าเริ่มต้น |
| `deep` | ระบบสำคัญมากหรือโปรเจกต์ใหญ่ |

ตรวจเฉพาะบางส่วนได้ เช่น โฟลเดอร์เดียว หรือเฉพาะโค้ดที่เปลี่ยนระหว่างสอง commit

## 🔄 6 ขั้นของ Full audit

1. **Reconnaissance** สำรวจโครงสร้างและขอบเขตความปลอดภัย
2. **Hunting** ล่าช่องโหว่แบบไล่ครอบคลุมทีละส่วน (ใช้ sub-agent หลายตัวพร้อมกัน)
3. **Validation** พิสูจน์ช่องโหว่ที่เจอ
4. **Structured output** บันทึกผลเป็น JSON ตาม schema
5. **Verification** ให้ agent อีกตัวตรวจผลซ้ำแบบอิสระ
6. **Reporting** เขียนรายงานสรุป

ผลแต่ละข้อจะได้สถานะ `confirmed` (ยืนยันแล้ว), `needs_validation` (ต้องตรวจเพิ่ม) หรือ `rejected` (ไม่ใช่ช่องโหว่)

## 📁 ไฟล์รายงาน

ค่าเริ่มต้นเขียนไว้นอกโปรเจกต์ที่ `~/security-audit-skill/<ชื่อ repo>/run-<N>/`

| ไฟล์ | เนื้อหา |
|---|---|
| `REPORT.md` | รายงานสรุป |
| `FINDINGS-DETAIL.md` | รายละเอียดช่องโหว่แต่ละข้อ |
| `NEEDS-VALIDATION.md` | รายการที่ต้องตรวจเพิ่ม |
| `findings.json`, `coverage-ledger.json` | ข้อมูลแบบ machine-readable |

ถ้ารันซ้ำ มันจะอ่านผลรอบก่อนแล้วตรวจต่อจากเดิม

## ⚠️ ข้อควรรู้

- **ต้องมี Node.js** สำหรับสคริปต์ตรวจรูปแบบรายงาน
- **ไม่รันโค้ดของโปรเจกต์ถ้าไม่มี sandbox:** การ build หรือรันโค้ดเป้าหมายต้องอยู่ใน sandbox ที่ปิดอินเทอร์เน็ตและจำกัดสิทธิ์ ถ้าไม่มี ช่องโหว่ที่ต้องรันพิสูจน์จะได้สถานะ `needs_validation` แทน
- **ไม่แตะระบบจริง:** ไม่ยิงไปที่เซิร์ฟเวอร์ Production, API ภายนอก หรือข้อมูลผู้ใช้จริง
- **Full audit ใช้ token เยอะ** เพราะรัน sub-agent หลายตัว ถ้าอยากประหยัดให้บอกว่าใช้ `quick` หรือกำหนดขอบเขต
